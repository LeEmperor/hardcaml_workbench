# WB-022 — Meaningful generated-net annotations

## Request
Original size: **Ticket**. Explain autogenerated names such as _123 with meaningful
signal annotations while preserving the producer's actual object identity.

## Current baseline
Inspection rows preserve original names, source spans, producer and digests.
Structural hierarchy provides ports but not a complete signal correspondence graph.
FS1 does not claim reliable original-source mapping from generated names.
An annotation must therefore be separate from renaming hardware or rewriting reports.

## Scope
- Define an annotation record scoped to producer object and exact design/run identity.
- Adopt one explicit producer-supplied name-map or owner-authored annotation source.
- Display meaningful label alongside the immutable original identifier.
- Retain annotation origin, ambiguity and stale/unmapped states in detail/search.

## Out of scope
Heuristic hardware renaming, editing netlists/reports, reconstructing optimized logic,
and implementing full RTL/OCaml source navigation.

## Acceptance criteria
1. _123 can show a meaningful annotation without replacing its canonical identity.
2. Equal-looking names in different scopes/runs cannot share an annotation accidentally.
3. Annotation detail identifies its source and exact mapping or explicit owner assertion.
4. Ambiguous/stale annotations are visible and cannot silently become authoritative names.
5. Original names remain searchable and exported evidence preserves producer identity.

## Dependencies
Required: delivered evidence identities; one annotation source is included in this ticket.
No additional ticket blocker; related: none required, since source-location mapping is optional.

## Estimate rationale
21 points cover one annotation contract, ingestion source and evidence presentation path.
Exclude hardware transformations, complete compiler naming recovery and source-navigation UI.

## Assumptions and decisions needed
Default: annotation plus original name, never replacement.
TBD: first annotation source, stable object-key scheme and persistence location.
Owner assertions must be labeled as such rather than presented as producer-derived facts.
