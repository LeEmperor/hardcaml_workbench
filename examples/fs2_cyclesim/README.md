# FS2 real Cyclesim provider

This is an independent, PDK-free Dune project. It needs the selected OCaml switch's
`core`, `ppx_jane`, `hardcaml`, and `hardcaml_workbench_provider` packages.
It does not depend on the ASIC example, ASIC provider, physical tools, or the
Workbench backend. `test_provider.exe` links only Core and the public provider
library, and launches the separate, unchanged `counter.exe` hardware checker.
The Python adapter and fixture codec remain independent conformance references.

## Build and prove the actual hardware simulation

From the Workbench checkout:

```sh
ls /tmp/opencode
scripts/with-switch.sh dune build \
  --root "$PWD/examples/fs2_cyclesim" \
  --build-dir /tmp/opencode/native-provider-acceptance -j 6 counter.exe test_provider.exe
python3 scripts/test-fs2-provider.py \
  --counter /tmp/opencode/native-provider-acceptance/default/counter.exe
```

The proof retains requests, event streams, stdout/stderr, reports, VCDs and hashes
under a new `/tmp/opencode/fs2-provider-*` directory. It checks directed wrap and
synchronous clear, a fixed-LCG seeded enable pattern, maximum uint64 seed, repeated
signal-body equality, and actual injected checker failures. Each cycle compares
the simulated four-bit register against an independent integer reference model.
The waveform is generated by `Hardcaml.Vcd.wrap` around the actual Cyclesim circuit.
VCD headers contain a date; deterministic replay compares the signal data body.

## Configure any project root

Create `hardcaml-workbench-simulation.sexp` in your project. Substitute the actual
absolute prebuilt executable paths; no build is performed by the provider or daemon:

```sexp
((schema_version 1)
 (provider_executable /absolute/install/test_provider.exe)
 (provider_args (--counter /absolute/install/counter.exe))
 (discovery_timeout_seconds 10)
 (run_timeout_seconds 90))
```

Discover `counter`, then explicitly select any of `wrap`, `reset`, `seeded`, a
canonical uint64 decimal seed, and all parameters:

| Parameter | Default | Domain |
|---|---|---|
| `cycles` | `64` | integer 32..100000 |
| `step` | `1` | `1`, `3`, `7` |
| `inject_failure` | `false` | `false`, `true` |

An injected failure flips the expected value at cycle 17: the DUT remains real,
the checker reports the observed mismatch, and case/suite outcome is `Failed`
with process exit zero. Domain/launch errors instead terminate the provider with
nonzero exit and an incomplete structured stream. Every case emits live flushed
progress, a closed actual VCD, a closed check report, and an explicit result.
Full uint64 seeds are converted to the same signed 64-bit LCG bit pattern without
floating-point conversion. ASIC references are empty for this project-only demo.

`--counter PATH` is optional when `counter.exe` is installed beside the provider.
Only the adapter depends on the provider package; the simulator does not.
For a private package installation, build with
`OCAMLPATH=/tmp/opencode/native-provider-prefix/lib scripts/with-switch.sh dune build ...`.
Discovery and run require no Python or Workbench checkout after installation.

## Native migration equivalence acceptance

The following harness takes **prebuilt** executables, never builds or installs, and
creates private projects/configs and daemon state. Both Python adapters/codecs stay
as independently parsed references. Substitute the actual prebuilt FIFO paths:

```sh
scripts/with-switch.sh python3 scripts/test-native-provider.py \
  --counter-provider /tmp/opencode/native-provider-acceptance/default/test_provider.exe \
  --counter /tmp/opencode/native-provider-acceptance/default/counter.exe \
  --fifo-provider /absolute/prebuilt/test_provider.exe \
  --fifo-simulator /absolute/prebuilt/fifo_sim.exe \
  --daemon /absolute/prebuilt/daemon/main.exe
```

Omit `--daemon` for standalone equivalence. `--fifo-root` selects the sibling
checkout containing the independent Python reference. `--evidence` names a new
directory; the default is a fresh `/tmp/opencode/native-provider-*` directory.
Use `--only counter` or `--only fifo` for staged checks; only that adapter's
executable flags are required in this mode.
It compares parsed discovery and every event for full suites and individual cases,
zero/max-uint64 seeds and real injected checker failures, then compares report
bytes and all VCD bytes except the date stanza. Invalid native selections must
exit nonzero before any event/artifact. HTTP mode checks captured selections,
paged artifact bytes/digests and persisted attempts after a private daemon restart.

## Native HTTP and terminal PTY acceptance

With the native implementation available, build serially at the allocated budget:

```sh
scripts/with-switch.sh dune build \
  --build-dir /tmp/opencode/fs2-build-provider/native -j 6 \
  daemon/main.exe terminal/main.exe
scripts/with-switch.sh python3 scripts/test-fs2-native.py
```

The script launches a real private daemon and uses native HTTP S-expressions. It
creates a project/config/state/home/tmp tree in `/tmp/opencode/fs2-native-*` and
retains raw request/response JSONL, daemon logs, PTY screens/ANSI, a VCD, viewer
receipt and `result.json`. `--daemon`, `--client`, and `--counter` override the
prebuilt executables. `--skip-pty` is an HTTP-only diagnostic, not full acceptance.
The harness never invokes a build. Run it in the selected switch environment so
the daemon can inspect the empty Dune fixture project.

Checks include deduplication/conflict, targeted rerun lineage and captured inputs,
semantic failure versus process failure, malformed/duplicate/truncated/gapped/
wrong-identity/post-terminal streams, missing artifacts, partial cancellation,
discovery mismatch, real Cyclesim/rerun, multi-page arbitrary-byte/hash transfer,
two independent simulation tiles, explicit terminal viewer handoff, durable
history after restart without replay, unclean daemon interruption with retained
partial results, corrupt history, and changed/missing private artifact copies.
The PTY also edits the delivered multi-step launch form, observes a real checker
failure and job logs, and submits a distinct targeted rerun through the palette.
The recording viewer actually runs as an external executable with the exported
local file; no graphical viewer is needed.

## Deterministic fault fixture

`scripts/fixtures/fs2_provider.py --control ABS_JSON --calls ABS_JSONL` is an
alternative provider prefix. Control is `{"mode":"pass"}` and is read on each
invocation; calls append operation/mode/request records. Its two cases are `first`
and `second`, seed default `42`, with no parameters. Supported modes:

`pass`, `fail`, `malformed`, `duplicate`, `truncated`, `gap`, `wrong-attempt`,
`missing-finished`, `post-finished`, `nonzero`, `slow`, `cancel`,
`missing-artifact`, `rejected-artifact`, `discovery-malformed`,
`discovery-version`, `discovery-mismatch`.

`slow`/`cancel` finish the first case then emit indeterminate progress for up to
60 seconds in the second, allowing supervisor cancellation or daemon interruption.
Binary fixture traces deliberately contain NUL, non-UTF8, CRLF and exceed one
64-KiB byte page. Changed/missing durable evidence is tested by modifying only
the harness's own copied daemon artifacts after a valid capture.
